# Remova 项目全面评审

- **日期**: 2026-09-15
- **版本基线**: 工作区 1.2.0-dev（含 IObit 壳、启动项扩展、计划任务列修复、服务可读化；未发布）
- **评审范围**: 用户体验 / 产品功能 / 开发实施 + 行业对比
- **对比对象**: Geek Uninstaller、HiBit Uninstaller、IObit Uninstaller、Revo Uninstaller、Bulk Crap Uninstaller（BCU）

---

## 1. 用户体验（UX）

### 1.1 优势

| 点 | 说明 |
| --- | --- |
| 主路径清晰 | 行内「卸载」→ 官方卸载器 → 成功后残留扫描，符合 Windows 用户心智 |
| 侧栏五模块 | 软件 / 启动项 / 服务 / 计划任务 / 更多，接近消费级工具 IA |
| 浅色 IObit 风 | 圆角卡片、蓝色主色、大图标，比「取证表」更亲和 |
| 分类 chips | 全部 / 桌面 / Store / 大体积 / 最近安装，降低长列表认知负担 |
| 全局反馈 | notice/error 提升到 Shell 层；分析/孤儿/监控会跳回软件页 |
| 双语 | zh/en 键位对齐，默认中文 |

### 1.2 劣势

| 点 | 说明 |
| --- | --- |
| 服务仍难懂 | 过滤驱动后仍偏多；Description 常为空或极短，用户难判断能否禁用 |
| 计划任务噪声 | 去掉 Microsoft\Windows 后仍可能有大量 OEM/更新任务，缺少「仅第三方」默认筛选 |
| 启动项缺口 | 尚未覆盖 UWP/Store 启动任务（任务管理器有、本工具可能没有） |
| 高级操作偏深 | 强制清理、忽略规则在「更多」卡片，需二次进入；缺少行内「更多操作」 |
| 空/错态文案 | 有 emptyList，但服务/任务加载中仅复用 estimatingSizes，语义不准 |
| 无「一键体检」 | 行业软件常有 Health/扫描首页；Remova 无汇总入口 |

### 1.3 机会

- 服务默认「仅运行中 / 仅非 Microsoft」筛选 + 更醒目的启动类型徽章
- 计划任务默认「仅非系统路径」+ 按任务文件夹分组
- 软件页行内 `…` 菜单（深度分析 / 强制清理 / 忽略）减少跳转
- 首页轻量摘要：已装 N 个、可回收约 X GB、上次清理记录

### 1.4 威胁

- 功能继续堆叠会再次破坏「新手友好」目标
- 禁用系统相关服务/任务误伤稳定性 → 需要更强保护与说明
- 与任务管理器/设置应用信息不一致会造成信任下降

### 1.5 SWOT（UX）

| | 正面 | 负面 |
| --- | --- | --- |
| **内部** | **S** 主路径+侧栏已消费级化 | **W** 服务/任务可读性与默认筛选弱 |
| **外部** | **O** 向 IObit/Geek 的心智对齐空间大 | **T** 功能膨胀与误操作风险 |

## 2. 产品功能

### 2.1 优势

| 能力 | 状态 |
| --- | --- |
| 装机列表 HKLM64/32 + HKCU + Store | 有 |
| 深度关联扫描（目录/快捷方式/TEMP/注册表/服务/任务…） | 有 |
| 官方卸载（含 MSI/Store PowerShell）+ 等待超时 | 有 |
| 备份 → 清理 → 会话还原 | 有 |
| 批量清理、孤儿扫描、安装监控 | 有 |
| 启动项/服务/任务启用禁用 | 有（启动项源已扩展） |
| 安全闸门（关键服务/浅路径/系统根） | 有 |

### 2.2 劣势

| 点 | 说明 |
| --- | --- |
| 无浏览器扩展清理 | HiBit/IObit 常见；Remova 未做 |
| 无 UWP 启动任务 | 任务管理器「启动应用」含 UWP，本工具启动项以注册表+文件夹为主 |
| 无便携模式/无安装器静默参数文档 | 部分竞品支持 portable |
| 无磁盘健康/软件健康评分 | 可选；若做需可解释，避免黑盒 |
| 上下文菜单能力有限 | 仅 `--analyze`，无「卸载选中」直达 |
| 多语言仅 zh/en | 行业软件常 20+ 语言 |

### 2.3 机会

- 浏览器扩展（Chrome/Edge/Firefox）扫描清理
- UWP 启动任务（`StartupTask` / Package manifest）
- 便携版 zip + 免安装
- 「软件健康」仅展示可行动建议（残留/启动项/大体积），不做玄学分

### 2.4 威胁

- Store 应用卸载策略变化
- 杀软对强制删除/注册表写入的误报
- 需要管理员才能写 HKLM/服务，权限体验摩擦

### 2.5 SWOT（功能）

| | 正面 | 负面 |
| --- | --- | --- |
| **内部** | **S** 卸载+备份+监控闭环完整 | **W** 浏览器/UWP/便携缺口 |
| **外部** | **O** 差异化「证据级清理」可信度 | **T** 平台权限与商店限制 |

## 3. 开发实施

### 3.1 优势

| 点 | 说明 |
| --- | --- |
| 测试基线 | `cargo test --lib` 58；pipeline dry-run/backup/delete/restore |
| 安全可测 | 关键服务拒绝、受保护路径拒绝有单测 |
| 性能 | 应用列表虚拟化；图标缓存；异步命令 |
| 结构 | Rust 扫描/执行/备份分层；前端 Shell/页面组件拆分 |
| 构建 | tauri build 稳定；NSIS+MSI |

### 3.2 劣势

| 点 | 说明 |
| --- | --- |
| `App.tsx` 仍偏大 | 软件页逻辑集中，后续难测 |
| 无统一数据层 | 多处裸 `invoke`（ARCH-3 未做） |
| `thiserror` 未落地 | 错误多为 `String`（ARCH-5） |
| 管理列表无虚拟化 | 服务 890 条时 DOM 压力大 |
| 后端硬编码英文启动类型 | `Auto/Manual/Disabled` 写死在 detail 字符串 |
| schtasks 依赖位置列 | 列顺序变更会静默错位；缺契约测试 |
| 前端测试几乎只有 semver | UI/流程无组件测试 |

### 3.3 机会

- `useManageList` / `useApps` 数据 hook；组件测试（testing-library）
- `OfficialUninstall`/`ScheduledTask` 解析增加 CSV fixture 测试
- 管理列表虚拟化与「仅运行中」筛选在 Rust 侧完成
- CI 增加 `cargo clippy -D warnings` 收紧

### 3.4 威胁

- Windows API/编码/locale 回归成本高
- 单文件膨胀导致协作与审查变慢
- 发布流程手工步骤多，易漏 CHANGELOG/三处版本号

### 3.5 SWOT（实施）

| | 正面 | 负面 |
| --- | --- | --- |
| **内部** | **S** Rust 安全闸门与冒烟测试 | **W** 数据层/错误类型/前端测试薄 |
| **外部** | **O** Tauri 生态与 CI 可加强 | **T** Win32 编码与权限矩阵复杂 |

## 4. 行业对比

| 维度 | Remova 现状 | Geek | HiBit | IObit | Revo | BCU |
| --- | --- | --- | --- | --- | --- | --- |
| 主界面 | 侧栏+卡片，浅色 | 紧凑列表 | 多模块 | 消费级卡片 | 专业列表 | 高密度表 |
| 一键卸载 | 有（官方优先） | 有 | 有 | 有 | 有 | 有 |
| 残留扫描 | 有（证据分+风险） | 强制删除 | 有 | 有 | 强 | 有 |
| 备份/还原 | 有 | 弱 | 有 | 有 | 强 | 有 |
| 启动项 | 注册表+文件夹 | 有 | 有 | 有 | 有 | 有 |
| UWP 启动 | **缺** | 部分 | 有 | 有 | 部分 | 部分 |
| 浏览器插件 | **缺** | 部分 | 有 | 有 | 部分 | 部分 |
| 服务管理 | 有（已滤驱动） | 无/弱 | 有 | 有 | 弱 | 部分 |
| 计划任务 | 有（已修列） | 弱 | 有 | 有 | 弱 | 有 |
| 安装监控 | 有 | 无/弱 | 有 | 有 | 弱 | 部分 |
| 批量 | 有 | 有 | 有 | 有 | 有 | 强 |
| 便携版 | **缺** | 有 | 有 | 无/部分 | 无 | 有 |
| 开源 | 是 | 否 | 否 | 否 | 否 | 是 |
| 安全闸门+测试 | 较强 | 黑盒 | 黑盒 | 黑盒 | 黑盒 | 中 |

**定位结论**: Remova 在「证据级残留 + 备份安全」上有差异化，UI 已接近消费级；短板是 **UWP/浏览器清理、便携、管理列表性能与默认可筛选性**。不必抄健康分，应强化「可解释的安全清理」。

## 7. 结论

- **产品定位**应继续：安全可解释的深度卸载，而不是功能大而全。  
- **体验瓶颈**在管理模块的「可扫描性」（默认筛选、虚拟列表、可读详情）。  
- **工程瓶颈**在数据层与测试广度；发布前应完成 1.2.0 用户试用再合并主分支 tag。
