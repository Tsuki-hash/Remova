# Remova × AI 智能化功能方案

> 状态：设计定稿，待按里程碑实施  
> 版本基线：1.2.1（UX 热修后）  
> 用途：后续 AI 相关开发的唯一 backlog / 架构依据；完成一项在此勾选并回填日期  
> 约束：AI **不得**绕过 `safety` 门禁、备份与用户确认执行删除

---

## 0. 设计原则

Remova 的差异化是「**证据级可解释 + 可备份回滚**」。AI 只放大这一点，不替代安全链路。

| 原则 | 含义 |
|---|---|
| **AI 不执行删除** | 真删仍走 `safety` + 确认 + 备份；模型只影响解释 / 排序 / 勾选建议 |
| **默认本地、云可选** | 路径与注册表片段默认不上传；云模型需显式开启并脱敏 |
| **可解释优先于“聪明”** | 每条 AI 建议必须能回指现有 `Evidence`；禁止黑盒“我觉得该删” |
| **失败可降级** | 无网 / 无 Key / 超时 / 模型拒绝时，产品 100% 可用（沿用规则引擎） |
| **隐私最小化** | 默认只上送：软件名、发布者、脱敏路径、证据 code/weight；不传文件内容、浏览器库、剪贴板 |

## 1. 与现有卸载流程的整合点

现有主链路：

```text
列表 → 官方卸载 → 残留扫描(证据评分) → 人工复核 → 备份 → 清理 → 还原/报告
```

| 阶段 | 整合点 | AI 产物 | 用户动作 |
|---|---|---|---|
| 列表 | Copilot 搜索（P2） | 筛选条件 | 进入目标软件 |
| 官方卸载 | （可选）捆绑提示 | 一句话摘要 | 卸载 |
| **残留复核** | 扫描完成后对 items 批量 explain | 每行摘要 + 建议勾选 | 勾选/取消 |
| 确认清理 | Modal 风险叙事 | 影响说明 | Hold 确认 |
| 执行 | **无 AI** | — | 备份+删除（现逻辑） |
| 报告 | 摘要卡 + 失败建议 | 人话总结 | 重试 / 打开备份 / 还原 |

**明确不做**：让模型判定 System32 是否可删、写注册表、`sc delete` 等写操作。

## 2. 功能清单

### A1. 残留智能识别与解释（Residual Explainer）

| 项 | 内容 |
|---|---|
| **场景** | 用户看到 `AppData\Local\Foo\Cache` 等路径，不确定为何出现、该不该删 |
| **现状** | `scanner` 已有 score + `Evidence`，UI 仍偏取证表 |
| **实现** | ① 将 `CleanupItem.evidence` 组装为结构化 JSON；② LLM 生成「为何是残留 / 删了会怎样 / 建议是否勾选」；③ 输出按 `path` 绑定；④ 仅对 Suspected / 高分项调用，控制 token |
| **命令草案** | `ai_explain_items(app, items[]) → [{ path, summary, risk_narrative, suggest_check }]` |
| **价值** | 把「敢删」从专家产品拉到消费级 |
| **禁止** | 不改 score 阈值；不自动清理；`suggest_check` 不得勾选 high risk |

---

### A2. 卸载风险评估叙事（Risk Narrative）

| 项 | 内容 |
|---|---|
| **场景** | 强制清理 / 批量卸载 / 禁用服务前，需要人话风险说明 |
| **现状** | 高风险红边 + hold-to-confirm 已有，文案仍是模板 |
| **实现** | 汇总目标软件、将删项 kind 分布、是否含 Run/Service/Task、是否共享目录 → 生成「可能影响 X；默认不勾 Y」；写入危险操作 Modal |
| **价值** | 降低确认疲劳、提升信任；成本低 |
| **成本** | 单次短生成，可缓存 |

---

### A3. 关联 / 共享组件分析（Shared Runtime Graph）

| 项 | 内容 |
|---|---|
| **场景** | 卸掉 VC++ / .NET / DirectX / Python / Node 后其它软件损坏 |
| **实现** | **规则优先**：同 Publisher、同 InstallLocation 前缀、已知 runtime 名单、Uninstall GUID 家族；对「高分但疑似共享」打 `shared` 徽章；可选 LLM 仅对 *名称+发布者* 做「是否运行库」分类 |
| **输出** | 复核列表「共享组件」标记；默认不勾；强制清理 Modal 特别提示 |
| **价值** | 直接降低「卸一个坏一片」——卸载器口碑生死线 |
| **难度** | 中 |

---

### A4. 自然语言交互式卸载（NL Uninstall Copilot）

| 项 | 内容 |
|---|---|
| **场景** | 「把上个月装的三个游戏卸干净」「找出占用最大的 Adobe 并清理」 |
| **实现** | ① LLM：自然语言 → **意图 JSON**；② 本地：用现有 `filtered` / `analyze` / `batch` 执行；③ UI：Copilot 面板只出「计划预览」，用户确认后才 invoke |
| **意图 Schema** | `{ filter: { name_like, publisher, size_gt_kb, installed_after }, action: "list"|"analyze"|"batch_uninstall"|"force_clean", include_leftovers: boolean }` |
| **安全** | `batch_uninstall` / `force_clean` 必须走现有 Confirm + 复核；Copilot **不能**自动点确认 |
| **难度** | 高（对话状态、误解析、多语言） |

---

### A5. 智能忽略 / 信任规则建议（Smart Trust）

| 项 | 内容 |
|---|---|
| **场景** | 同一批共享运行库反复出现在残留列表 |
| **实现** | 基于历史清理与反复 skip 的路径模式，建议加入忽略列表/发布者白名单；文案说明原因 |
| **价值** | 长期降噪；数据已在 `history` / `ignore` |

---

### A6. 报告解读与事后建议（Report Copilot）

| 项 | 内容 |
|---|---|
| **场景** | 清理后要懂「释放了什么、要不要重启、失败怎么办」 |
| **实现** | `FullCleanupReport` + `item_details` 结构化喂给模型 → 摘要卡片；失败项分层：可重试 / 需管理员 / 被占用 |
| **价值** | 对齐已做的报告大数字卡片；与 A2 共用管道 |

---

### A7.（远期）安装前预判 / 捆绑检测

安装监控差分 + 模型描述第三方组件写入。依赖 `installmon` 质量，放在 A1–A3 稳定之后。

## 3. 优先级矩阵（用户价值 × 实现难度）

| 优先级 | 功能 | 价值 | 难度 | 说明 |
|:---:|---|:---:|:---:|---|
| **P0** | A2 风险叙事 | 高 | 低 | 体感立刻提升 |
| **P0** | A1 残留解释 | 高 | 中 | 与复核页强绑定 |
| **P1** | A3 共享组件标记 | 高 | 中 | 规则 80% + AI 20% |
| **P1** | A6 报告解读 | 中高 | 低 | 共用 LLM 管道 |
| **P1** | A5 智能忽略建议 | 中 | 低 | 复用 history |
| **P2** | A4 NL Copilot | 高 | 高 | 依赖 P0/P1 证据层 |
| **P3** | A7 捆绑预判 | 中 | 高 | 依赖安装监控 |

**排序逻辑**：先让已有扫描结果更可信、更好懂（A1/A2/A6）→ 补关系图（A3/A5）→ 最后做对话入口（A4）。

## 4. 整体架构

### 4.1 模块划分

```text
┌─────────────────────────────────────────────┐
│ UI 层                                        │
│ 残留 AI 说明条 · 风险 Modal · Copilot 面板    │
│ 报告摘要卡 · 忽略建议                        │
└───────────────────┬─────────────────────────┘
                    │ invoke
┌───────────────────▼─────────────────────────┐
│ AI 编排层（新） src-tauri/src/ai.rs          │
│ prompt-builder · 脱敏 · 缓存 · 超时降级      │
│ Provider: OpenAI 兼容 / Ollama / 自定义 URL  │
└───────────┬─────────────────────┬───────────┘
            │ 只读查询            │ 配置
┌───────────▼───────────┐  ┌──────▼────────────┐
│ 现有核心（不可绕过）    │  │ 本地知识（可选）   │
│ scanner / safety       │  │ runtime 名单      │
│ executor / backup      │  │ 共享组件图        │
│ history / ignore       │  │ 解释结果缓存      │
└────────────────────────┘  └───────────────────┘
```

### 4.2 技术实现要点

1. **独立模块** `src-tauri/src/ai.rs`（推荐后端编排，便于统一密钥与脱敏）  
   - 命令：`ai_explain_scan`、`ai_risk_brief`、`ai_parse_intent`、`ai_summarize_report`  
   - 全部 `async` + 超时（8–15s），失败返回 `Ok(None)` 或结构化 `disabled`，不抛死错误

2. **设置页「智能」**  
   - 关闭（默认）/ 本地模型 / 云 API  
   - BaseURL + API Key + 模型名（OpenAI 兼容协议）  
   - 开关：「仅发送脱敏元数据」（默认开）

3. **脱敏策略**  
   - 用户目录仅保留 `AppData\Local\<Vendor>\<Product>` 层级  
   - 保留文件名；绝对路径可哈希  
   - **禁止**发送：文件内容、浏览器数据库、完整 hostname 用户名（可选打码）

4. **缓存**  
   - key = `hash(app_key + path + evidence_codes)`  
   - TTL 建议 7 天；离线命中缓存仍展示

5. **成本控制**  
   - 只对 suspected + 每 app 前 20 条高分项解释  
   - 批量卸载每 app 仅 1 次 risk brief  
   - 规则引擎优先，AI 为增强层

6. **UI 约定**  
   - 复核行 `ⓘ` 旁「AI 说明」；未启用时显示「未启用智能说明」  
   - 文案固定后缀：「模型建议，以证据为准；清理前可备份」  
   - Copilot 只渲染「计划卡」，确认后走现有命令

## 6. 风险与合规

| 风险 | 缓解 |
|---|---|
| LLM 误判导致误删 | 不改 safety；高风险默认不勾；全文案强调可还原 |
| 隐私泄露 | 默认关云；脱敏白名单；设置页明示发送字段 |
| API 卡死 | 超时降级，不阻塞清理主路径 |
| 成本失控 | 缓存 + 限量 + 仅 suspected |
| 用户不信任 AI | 始终展示证据原文；标注「以证据为准」 |
