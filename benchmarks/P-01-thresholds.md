# P-01 性能与容量阈值

**状态：待维护者确认。** 下表是提议的默认值；确认（或调整）并提交后，测量结果才能作为「无超阈值回归」的证据。事后按实测结果回填阈值属于作弊，评审不予承认。

## 1. 适用范围

| 项目 | 值 |
|---|---|
| 参照版本 | 上一个已发布且已知可用的 tag（测量时填写） |
| 被测版本 | 当前候选 commit（测量时填写） |
| 测试机器 | 4 核 / 8 GB / SSD / Windows 11 x64（测量时按实际填写） |
| 数据规模 | 应用数约 150；扫描 fixture 1 万与 10 万项；备份 fixture 1 GB |

## 2. 阈值（提议值，待确认）

绝对值取「普通办公机可接受」的上限；相对变化取「不构成可感知退化」的范围。

| 指标 | 绝对上限 | 允许相对变化 | 测量方法 |
|---|---|---|---|
| 冷启动到可交互 | 3000 ms | +20% | 第 3 节 |
| 应用列表首屏渲染 | 1500 ms | +20% | 第 3 节 |
| 扫描 1 万项目录 | 30000 ms | +20% | 第 3 节 |
| 扫描 10 万项目录 | 300000 ms | +20% | 第 3 节 |
| 取消响应（点击到停止） | 500 ms | +20% | 第 3 节 |
| 峰值工作集（空闲） | 250 MB | +20% | 第 3 节 |
| 峰值工作集（扫描中） | 500 MB | +20% | 第 3 节 |
| 备份 1 GB 数据 | 60000 ms | +20% | 第 3 节 |

**取值依据**：冷启动 3 秒是桌面工具的可接受上限；取消响应 500 ms 对应「点击后立刻有反馈」的感知阈值；扫描按每秒约 350 项估算（1 万项约 30 秒）；工作集上限按 150 个应用的列表加扫描峰值估算并留出余量。

**如果这些值与目标硬件或用户预期不符，请直接改数字**，不要迁就测量结果。

## 3. 测量方法

1. 同一台机器、同一份数据、同一 OS 状态，先测参照版本，再测候选版本。
2. 每个指标重复 3 次，冷缓存与热缓存分开记录。
3. 记录中位数与最差值（p95 或最大值），不要只报最好的一次。
4. 原始数据（每次运行的数值、日志、截图）随结果归档。
5. 第三方程序耗时（如供应商卸载器）不计入 Remova 自身指标。
6. 启动与工作集可用 `scripts/acceptance/measure-perf.ps1` 自动采集；扫描、取消与备份指标需按 `scripts/acceptance/README.md` 的 fixture 手工记录。

## 5. 判定规则

- 任一指标超过绝对上限 → P-01 不通过。
- 任一指标相对变化超过允许范围 → P-01 不通过，除非维护者书面接受并说明原因。
- 未测或数据不完整 → 记为「证据不足」，不得判为通过。
