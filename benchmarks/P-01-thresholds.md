# P-01 性能与容量阈值

**本文件必须先由维护者填写并提交，测量结果才能作为「无超阈值回归」的证据。**
事后按实测结果回填阈值属于作弊，评审不予承认。

## 1. 适用范围

| 项目 | 值 |
|---|---|
| 参照版本 | 待填（已发布、已知可用的旧版本 tag） |
| 被测版本 | 待填（当前候选 commit） |
| 测试机器 | 待填（CPU / 内存 / 磁盘类型 / OS 版本） |
| 数据规模 | 待填（应用数、目录项数、注册表项数） |

## 2. 阈值

每项都要给出**绝对值上限**与**相对参照版本的允许变化**。

| 指标 | 绝对上限 | 允许相对变化 | 测量方法 |
|---|---|---|---|
| 冷启动到可交互 | 待填 | 待填 | 见第 3 节 |
| 应用列表首屏渲染 | 待填 | 待填 | 见第 3 节 |
| 扫描 1 万项目录 | 待填 | 待填 | 见第 3 节 |
| 扫描 10 万项目录 | 待填 | 待填 | 见第 3 节 |
| 取消响应（从点击到停止） | 待填 | 待填 | 见第 3 节 |
| 峰值工作集（空闲） | 待填 | 待填 | 见第 3 节 |
| 峰值工作集（扫描中） | 待填 | 待填 | 见第 3 节 |
| 备份 1 GB 数据 | 待填 | 待填 | 见第 3 节 |

## 3. 测量方法

1. 同一台机器、同一份数据、同一 OS 状态，先测参照版本，再测候选版本。
2. 每个指标重复 3 次，冷缓存与热缓存分开记录。
3. 记录中位数与最差值（p95 或最大值），不要只报最好的一次。
4. 原始数据（每次运行的数值、日志、截图）随结果归档。
5. 第三方程序耗时（如供应商卸载器）不计入 Remova 自身指标。

## 5. 判定规则

- 任一指标超过绝对上限 → P-01 不通过。
- 任一指标相对变化超过允许范围 → P-01 不通过，除非维护者书面接受并说明原因。
- 未测或数据不完整 → 记为「证据不足」，不得判为通过。
