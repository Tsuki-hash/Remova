对齐部分缺口
1

查注册表 UninstallString

部分
目标

识别 MSI / Inno / Squirrel，选对卸载命令

Remova

读 UninstallString + QuietUninstallString，优先静默；MSI 走 msiexec/GUID；Store 走 PowerShell；拆参按 CommandLineToArgvW

未显式标注 Inno / Squirrel / NSIS 安装器类型徽章

差在「类型可见」：命令选择已覆盖主要形态，但用户看不到「这是 Inno」以便预判静默参数。
2

全量扫描 7 类残留

对齐
目标

目录 · 服务 · 驱动 · 注册表 · Shell/CLSID · PATH · 启动项/任务

Remova

安装目录/跨盘根、服务、驱动、Software/Uninstall、App Paths、CLSID/Shell、PATH、Run、Startup、计划任务、TEMP、快捷方式、WebView 面具

证据链 + 置信/风险分档

覆盖完整，并多出 TEMP / 快捷方式 / WebView 面具 / 跨盘产品根。
3

确认清单 + 风险预告

对齐
目标

标出数据目录风险 + 预告「要弹 UAC」

Remova

清理结论卡：可清 / 需确认 / 为何保留；风险层级；用户库子目录默认不勾

管理员状态角标 + 提权确认框

UAC 预告可再提前：现在更多是「要提权时才弹」，可在确认清单顶部预测「本清单含 HKLM/Program Files，将请求管理员」。
4

官方卸载器静默跑

部分
目标

静默执行；exit 0 才算成功，让官方程序先清掉大头

Remova

优先 QuietUninstallString；等待退出并用 status.success() 判定；失败可继续强制清理路径

超时约 5 分钟；不强制「exit 0 未过则中止全流程」

语义可再严：目标把 exit 0 当硬闸门；Remova 更「失败仍可手工清残留」——更灵活，但少了「官方已清干净」的强证据。
5

一个提权脚本清残留

缺口
目标

系统级残留打包进一个提权脚本，只弹 1 次 UAC

Remova

整应用可「以管理员重启」一次提权；删除在进程内经 policy 门禁执行

不是「生成临时提权脚本 → 单次 runas → 回收」模型

结构差异：非管理员模式下多项系统删除可能多次碰壁；目标流程是把 HKLM/服务/驱动收敛到单次提升的脚本会话。这是最值得做的架构项。
6

非提权清 AppData

部分
目标

HKCU / 用户目录 / Temp 走普通权限，避免多余 UAC

Remova

AppData、HKCU、用户库子目录、TEMP 均在清理面；是否提权取决于会话本身

1.1.1 起：库根硬拒，库内子目录关联后可清（默认需确认）

未按权限分轨：用户级与系统级删除混在同一管道，没有「先无提权清用户侧」的明确阶段。
7

验证 checklist

部分
目标

每项给证据：服务 1060=已删、路径不存在、注册表键消失

Remova

清理后 verify_cleanup_leftovers：路径/注册表/PATH 是否仍在（✅/❌）

报告含已删/失败/跳过/延迟 + item_details 原因

缺「权威退出码字典」：未把 1060 / sc / schtasks 原生命令码映射成「证据级」文案，复核偏布尔存在性。
8

删临时脚本

缺口
目标

含 Key 的临时脚本必删，防泄露

Remova

当前不生成「含 Key 的提权脚本」；AI Key 走 DPAPI，失败不落明文

备份会话在 %PROGRAMDATA%\\Remova\\Backup，保留 7 天（非脚本）

随第 5 步成立：一旦引入临时提权脚本，本步成为安全硬门。现状无此攻击面，但是「未建」不是「已做」。

目标流程强调的 3 个「删干净」秘诀，对照 Remova 扫描器。

①

全盘跨盘搜索

对齐
Ollama 的 .ollama 在 C 盘和 D 盘各有一份，只扫 C 盘会漏。
Remova

scan_other_drive_roots：按产品名 slug 扫其它盘根下的产品目录

外加跨盘浅根、TEMP、快捷方式定位

结论：主路径有跨盘产品根扫描。仍非「全盘文件名深度遍历」，极深藏的点状文件可能靠名称匹配或用户拖入补充。
②

不放过伪装目录

对齐
Ollama 的 WebView2 缓存是 Roaming\ollama app.exe\EBWebView（56M），按厂商名精确搜会漏。
Remova

scan_webview_masks / webview_mask_matches：按 exe 名面具识别 WebView 缓存目录

测试覆盖 ollama.exe / Ollama.exe，拒绝 chrome.exe 等误报

结论：正是为这类「以 exe 命名的缓存壳」设计的，与秘诀②同构。
③

区分「缓存」和「用户数据」

部分
C:\Users\Aaron\Nutstore 像用户文件，实为客户端镜像缓存；Documents\坚果云同步冲突 反而是真笔记，需 diff 比对后再删。
Remova

库根 + 同步冲突目录 = 红线永不删

库内子目录（Documents\某App）= 可关联清理，默认「需确认」

AppData / updater = 正常残留面

缺「镜像缓存识别」与「冗余 diff」：Nutstore 这类根下镜像目录不会自动升为「缓存建议清」；也没有「两处内容 diff 确认冗余后再删」的辅助，只能靠用户判断。

UAC 预告写进确认清单减少「点完才吓一跳」部分

若只做三件事（建议 1.2）

  1. 单次提权清理会话
    生成无密钥的残留清单脚本 → 1 次 UAC → 回写结果 → 立刻销毁。对齐步骤 5/6/8。
  2. 证据级复核
    服务 1060 / sc / schtasks / reg 退出码映射成「为什么算成功」。
  3. 缓存 vs 笔记启发式 + 可选 diff
    同名目录多盘镜像、体积大且非库根 → 建议清；对同步冲突/笔记类默认只提示。
